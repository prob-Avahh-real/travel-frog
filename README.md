# 旅行青蛙 (Travel Frog)

复刻《旅行青蛙》的放置养成游戏：收三叶草 → 买便当 → 给青蛙备行李 → 它出门 → 带回明信片和特产 → 攒图鉴升称号。

**界面是中文本地化版**：全部文案为中文，代码与产物里不得出现任何日文假名——这条由 `test/i18n.test.js` 看着（改动后 `npm test` 会直接变红）。

零依赖、零构建：打开 `index.html` 就能玩；同一份产物用 Capacitor 包成 App。

---

## 快速开始

```bash
open index.html          # 直接玩
npm test                 # 30 条自动化测试（引擎 + jsdom 端到端 + 中文本地化守卫）
npm run smoke            # 真浏览器冒烟（DOM 断言 + 控制台异常 + 截图）
npm run shot             # 导出一张手机截图到 /tmp/travel-frog-home.png
npm run build            # 同步产物到 www/（Capacitor 用）——改完前端必须跑
bash build.sh            # 出 Android APK（需 Android SDK + JDK 21）
bash build.sh --web-only # 只跑测试 + 同步 www/，明确不产 APK（CI 里跑这条）
```

调试参数：`index.html?reset=1` 清档 · `?fast=20` 加速 20 倍 · `?tab=shop` 直接打开某个面板。
桌面调试快捷键：`1`~`5` 打开面板 · `0`/`Esc` 回场景 · `H` 一键收割 · `F` 快进 5 分钟。

## 玩法要点

- **三叶草畦**：12 株，每株 45 秒长成（`js/data.js` 的 `CONFIG.garden` 可改）。点其中一株，或点顶部的「+」一键收割；约 1/30 概率额外掉 **四叶草**（带出门必得稀有以上明信片）。
- **商店**：8 种便当（价格决定距离档 near/mid/far/exotic）+ 7 种道具（推远行程 / 提高稀有度 / 打开只认道具的地方）。
- **行李**：1 个便当 + 1 个守护符（四叶草）+ 2 件道具 —— 正好 4 个格子，对齐原作的行李面板；出发时消耗，并预告「可能去到」哪些地方。
- **旅行**：真实时间流逝，关掉应用也在走；回来带 1 张明信片（地点 × 时段 × 姿态 × 文案）与 1~2 件特产。
- **图鉴**：14 个地点 × 3 张 = 42 张，没拍到的显示上锁。
- **特产**：卖掉换三叶草，或喂门口来的蜗牛换回礼（有概率回赠道具）。
- **称号**：按明信片数从「独自旅行的青蛙」升到「传说的旅蛙」。

## 界面结构（对齐原作的「一张画 + 几个钮」）

```
满屏场景（js/scene.js 画）  ← 树 + 屋里（梁/后墙/窗/架子/床/木台）+ 庭院（土畦/树桩桌/邮筒/栅栏）
├── 顶部悬浮：三叶草计数片 + 「+」一键收割 + 菜单片 + 出门行程小纸片
├── 左下木牌：准备        → 打开「行李」面板
├── 右下三个插画按钮：商店 / 行李 / 相册
└── 覆盖面板（各自带「返回」）：
    行李 = 2×2 四格（便当 / 守护符 / 道具 ×2）+ 「出发」
    商店 = 蓝条纹标题条 + 木板货架（一页 2×2 布包格）+ 价格牌 + 边缘翻页箭头 + 底部说明纸
    相册 = 42 张卡位网格 → 点开是「照片页」（一页一张：奶油卡 + 白边照片 + 页码 + 存图 + ×）
    菜单 = 称号 / 统计 / 特产 / 旅行动态
```

场景里只有三个动态槽位（`#tf-frog` / `#tf-clovers` / `#tf-snail`），UI 只替换槽位内容，不重画整张图。
行李的四个格子、商店的每页 4 格都由 `CONFIG.bag` / `SHOP_PER_PAGE` 推出，加格位不必改主循环。

## 架构

```
index.html          单页骨架（满屏场景 + 4 个覆盖面板）
css/style.css       全部样式（颜色/字体走 CSS 变量；含手表窄屏段）
js/data.js          所有数据表 + 默认配置
js/engine.js        状态机 / 时间推进 / 经济结算（纯逻辑，注入 now/rng/storage）
js/scene.js         青蛙家那张场景 + 青蛙本体（唯一渲染器）+ 三个动态槽位（纯函数）
js/art.js           明信片风景 / 道具图标 / 商店布包（纯函数；青蛙借用 scene.js）
js/ui.js            渲染 + 交互 + 弹窗（只替换槽位，不重画场景）
js/main.js          装配：真实时钟、存盘、主循环、键盘/体感输入
dev/design-ref/     原作截图 + 改版对比图 + 尚未对齐的清单（不进包）
dev/art-sheet.html  美术对开页（开发用，不进包）
test/               引擎测试 + jsdom 端到端 + 中文本地化守卫
scripts/            产物同步 + 真浏览器冒烟
```

**分层原则**：引擎不知道 DOM 的存在，UI 不知道游戏规则。所有副作用（时钟、随机、存档）从外部注入，因此引擎可以在 Node 里用假时钟 + 种子随机做确定性测试。

## 如何扩展（不动主循环）

| 想加什么 | 改哪里 |
|---|---|
| 新地点 | `LOCATIONS` 加一条：`dist` + `scene` + `scenes` + `souvenirs` |
| 新风景画面 | `js/art.js` 的 `FEATURES` 加一个 key 的函数 |
| 场景里的新家具/摆件 | `js/scene.js` 的 `sceneSVG()` 里加几行 `p()` / `ell()`（纯路径，无状态） |
| 新的动态槽位（例如再来一只访客） | `scene.js` 里加一个空 `<g id="tf-xxx">`，UI 按签名更新它 |
| 新便当 | `FOODS` 加一条（`dist` 决定走多远，`minMs/maxMs` 决定走多久） |
| 新道具 | `ITEMS` 加一条（`effects`: dist / duration / rare / times / guarantee） |
| 某地需要某道具 | 在**该地点**的 `requires` 写道具 id |
| 新明信片 | 该地点的 `scenes` 加一条 `[时段, 姿态, 文案, 稀有度]` |
| 新称号 | `TITLES` 加一条 `{min, name}` |
| 新面板 | `index.html` 加 `<section class="sheet" id="sheet-x">`，`ui.js` 的 `RENDERERS` 加一个 key |
| 行李多一格 | `CONFIG.bag` 改 `maxItems`/`maxCharms`，`index.html` 里加一个 `data-slot` 格子，`ui.js` 的 `fillSlot` 多调一行 |
| 商店一页多几格 | `ui.js` 的 `SHOP_PER_PAGE`（配上 `css/style.css` 的 `.board` 列数） |
| 商店货品换画法 | `js/art.js` 的 `bundleSVG`（布巾颜色由 id 哈希决定） |
| 场景加/改阴影层 | `js/scene.js` 的 `HATCHES`（排线）与 `STROKES`（色块内扫笔）数组，加一条坐标即可 |
| 调手绘手感 | `js/scene.js` 顶部：`INK`（墨色）、`W_MUL`（线宽总倍率）、`#sketch` 滤镜里的 scale（抖动幅度）、`STROKES`（色块内扫笔）、`HATCHES`（排线）——都是数字，改一个整体变调 |
| 调面板手绘 | `css/style.css` 的 `--wonky`/`--wonky-s`（圆角不等角程度）、`#ui-defs` 里 `#sketchUI` 的 `scale`（边框抖动幅度）、`nth-child` 那几条（歪斜角）；新面板只要加 `hand`（大面、抖动更强）或 `handy`（小件）类 |
| 调房间进深 | `js/scene.js` 顶部的 `VP`（消失点）与 `KROOM`（后墙收缩比，越大房间越浅）—— 屋里五个面、地板缝、侧墙上的门全部由它们算出来 |
| 加一件会"露顶面"的物件 | 用 `cyl(cx, baseY, rx, ry, hgt, 顶色, 侧色)`；它同时画出侧身和顶面椭圆，比手搓 path 稳 |
| 挪动土畦/石板路 | 改 `BEDQ`（土畦四点）与石板路那段的前后边；三叶草与热区会自动跟着走（同一个梯形） |
| 加一个手绘边框 | 给元素加 `hand`（大面：圆角大、抖动强）或 `handy`（小件）类即可 —— 边框由 `Art.sketchBox` 生成真路径、`ui.js` 的 `sketchBorders` 量尺寸后贴 |
| 调整配色 | `js/scene.js` 的 `C` 色板表 + `css/style.css` 的 `:root` 变量，两边要同步（面板与场景共用一套色） |
| 连拍视图复核 | `node scripts/smoke-browser.js --views=<目录>` —— 一次起浏览器拍 7 个视图；加视图就是往 `VIEWS` 里加一行 |
| 青蛙新姿态 | `js/scene.js` 的 `POSES` 加一条（部件开关：eyes / arms / legs / prop），守卫测试会检查数据与画法是否对得上 |

有一条测试会遍历所有地点、用「同档便当 + 该地 requires」跑 200 次，确认**每个地点都真的能被走到** —— 加内容时不会悄悄变成死代码。

## 踩过的坑（别再踩）

1. **jsdom 抓不到「给未声明变量赋值」这类致命错误。** 真浏览器在 strict 模式下会抛 ReferenceError 让页面整体白屏，jsdom 却放过去了——当时测试全绿，页面其实是空的。
   → 必须有 `npm run smoke` 兜底；这个盲区是被真浏览器冒烟抓出来的。
2. **无头 Chrome 的输出不要走管道。** Chrome 的 zygote 子进程会一直握着管道，`spawnSync` 永不返回。重定向到文件 + 硬超时（`scripts/smoke-browser.js` 已这么做）。
3. **`--dump-dom` 在有常驻 rAF 循环的页面上会挂住** → 改用 CDP `Runtime.evaluate` 取 DOM 并断言。
4. **截图前先删旧图。** 否则「截图已导出」会在旧文件上通过——传感器自己骗自己。
5. **地点解锁只能有一处真相源**，写在 `LOCATIONS[].requires`。曾经道具侧也声明 `enables`，两边对不上，导致「带了木碗也去不了温泉」。
6. **稀有度降级要退到最接近的更低档**，不能退到最低档：否则要 epic 的请求会掉成 common，「四叶草保底稀有」静默失效。
7. **不要每株弹一条提示**：一键收割曾一次弹 12+ 条提示糊满手机屏幕。现在合并成一条汇总，同屏最多 2 条。
8. **夜间配色不能压太黑**：初版夜景把远山画成一团黑块，完全看不出是哪个地点。
9. **坐标只能有一处真相源**：田位与蜗牛位置都由 `js/scene.js` 给出，UI 只按百分比定位热区。
   曾经 UI 里另写了一份坐标，改场景时热区就飘了——现在有测试逐株比对 UI 热区与 `scene.js` 的坐标。
10. **`www/` 是入库的产物**：改完前端不跑 `npm run build`，Capacitor 打出来的还是旧界面。
    现在 `test/i18n.test.js` 会逐文件比对源码与 `www/`，忘记同步直接变红。
11. **本地化别用「全局替换」交差**：日文词换成中文后出现了「库存（库存）」这种重复标题，
    机器替换完必须人眼过一遍界面（这次是靠真浏览器截图才发现的）。
12. **同一只角色别写两套渲染器**：曾经明信片里的青蛙（平涂）与家里的青蛙（勾线）长得不一样，改造型要改两处。
    已收敛：`js/scene.js` 的 `frogFigure(pose, opts)` 是唯一渲染器，明信片直接借用（`opts.night` 换深皮肤）；
    并加了守卫测试「明信片数据里用到的每个姿态都必须有画法」——新加姿态忘了画法会直接红。
13. **用 `innerHTML` 重建区块后，测试里先前抓到的节点是「死的」**：断言要重新 `qa(...)[0]` 取一次，
    否则会一边看着页面明明对了、一边报「没高亮」。这不是产品 bug，是架构（签名重建）带来的测试写法陷阱。
14. **行李格子是「排队」语义，不是固定槽位**：删掉第 1 件道具，第 2 件会顶上第 1 格。
    写测试时按「填了几格」断言，别按「第 N 格里必须是某件」断言。
15. **重描/描边只能描「看得见的轮廓」**：把树干右缘一路描到画面底部，可庭院段的树干已被草地盖住
    → 草地上凭空多出一条竖线。有叠盖关系时，后描的线要按「露出来的部分」截断。
16. **平涂 + 半透明晕染 = 塑料感**（本条是用户的直接反馈）：要「手绘」就走**线**——
    抖动笔触、排线阴影、色块内扫笔、纸纹；半透明色块只会让画面发灰发脏。
17. **给元素加 `position:relative` 之前，先查它原来是不是 `absolute`**：手绘样式类里的
    `position:relative` 把木牌、价格牌、关窗按钮、出门纸片的绝对定位顶掉了，它们会直接跑位。
    CSS 没有「没定位才加」的写法，只能显式补回。
18. **局部变量别和模块级常量重名**：家具「床」的四点与土畦的梯形都叫 `BEDQ`，结果 `quad()` 收到
    `undefined`，整幅场景渲染直接抛错。构建期不报、只有真跑一次才炸 —— 起名字前先看模块级有没有同名的。
19. **热区坐标别按字符串比**：CSSOM 会把 `'48.70%'` 规范化成 `'48.7%'`，断言要按数值比，
    否则红的是「格式」而不是「坐标不一致」这件真事。
20. **自动化点击要等「可点」，不是等「存在」**：出发按钮在没选便当前是 `disabled`——元素在
    DOM 里、点了没反应；出发之后还有一段「走下屏幕」的过场，不 `advance` 就仍是 `departing`。
    这类「存在但不可用」的元素，是自动化最常见的假通过。
21. **别把动物画成人**：青蛙的四肢要按真实解剖 —— 粗后腿 + 折起的小腿 + 带蹼平脚、前腿短细只有
    2-3 个小趾、两眼球鼓在头顶。画成人胳膊/人手，再精细也不像（用户原话：「按正常青蛙的四肢画，
    不要强行拟人」）。头还要比身子大（头宽 62 / 身宽 40）并整个压在身上，否则不萌。
22. **闭眼不要画白色眼球**：白眼球 + 一道弧线会读成「白眼上贴条线」，只在眼鼓包上画弧即可。
    这类问题缩略图看不出来，必须 1:1 放进真场景里看。
23. **CSS 边框做不出手绘**：四边一样直、角一样圆。手绘边框要生成真 SVG 路径（每条边一个带抖动的
    二次曲线 + 角上出锋 0-5%），由 JS 量出尺寸后贴覆盖层；CSS 那边连 `::before` 边框带滤镜一起删掉。
24. **jsdom 没有布局**（`offsetWidth` 恒为 0）：一切「量尺寸再贴」的 UI 在 jsdom 里必须优雅跳过，
    只有真浏览器冒烟能守住（断言 `.sk-border` 存在 + 路径够长 + `viewBox` 与实测尺寸一致）。
25. **正对面的角色像玩偶**：角色要侧着画；远侧肢体先画、颜色压深、位置略偏，否则侧面变成「一条腿」。
